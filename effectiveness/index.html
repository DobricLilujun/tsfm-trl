    Headline ranking¶

    beat naive is the share of cells where the model's MASE beats the naive row scored on the same (series, span, horizon) cell - not MASE < 1: MASE's denominator is the in-sample mean |delta| of the train span, so on these series naive itself sits near 4.5 and a MASE < 1 test calls everything a loss. The ratio column is the median of per-cell mase_model / mase_naive, which is comparable across data paths (same bytes, same split, same denominator on both sides); raw median MASE is scoped to this pass. ctx prints the context lengths actually used - different ctx is a different measurement. win is the number of windows sampled per cell, and --max-windows draws them uniformly at random from the test span, so the window count is part of the measurement, not a knob: switching seed at 8 windows moves naive's own MASE ~55% median (max 100%) and the paired model/naive ratio ~12% (max 25%); at 32 windows those fall to ~21% and ~7% (measured 2026-11-27 on four arena series, same bytes, same code). Worse than noise: the share is a threshold on that noisy ratio, and the ratio sits just above 1, so a small window count inflates it. Re-scoring the same 66 series at 32 windows instead of 8 lowered every model's share (chronos-bolt-small 42.4% -> 15.2%, arima 56.1% -> 40.9%) and moved one pairwise ordering; 32.3% of cells change winner between 8 and 32 windows. A single cell within ~12% of parity is neither a win nor a loss - read aggregate shares at 32 windows or more, not cells. no measurement counts cells whose windows were all non-finite or unscored; those never enter a median.

    Repeated cell keys: 2064¶

    These (model, series, span, horizon) keys were measured more than once in the merge inputs; the table keeps the newest. Every pair is classified by what changed. 2064 pairs asked the same question of the same bytes (same ctx, data_hash, window count) on a different stack - machine, torch build or commit - so their gap is the reproducibility spread. 0 pairs changed what was measured (context contract, data path, window sample): their gap is the size of that change, not noise. 0 pairs share a full signature, so their gap is run variance.

    Re-measured on another stack (same bytes, same protocol): naive (156), seasonal_naive (156), arima (156), chronos-bolt-small (156), chronos-bolt-base (156), chronos-t5-small (156), chronos-2 (156), timesfm-2.5-200m (156)

    Stack-to-stack gap on those pairs: median 0.000%, max 21.074% - the per-family version of this number is probes/trux/cross_machine_check.py.

    Quote a model's ranking only where its gap to the next model exceeds the spread above and the series-level confidence interval from probes/pass4_share_bootstrap.py; a share is a resample of ~100 series, so two models whose intervals overlap are tied however the table orders them.
